# 手机日程管理与离线同步

电脑接收消息并自动生成待办，同时保存权威数据库。安卓 App 保存一份本地数据，支持列表、月历、新建、修改标题与人工备注、修改截止时间、完成、恢复、删除、置顶、紧急标记和稍后提醒。

## 配对与使用

1. 先升级电脑端，再安装配套 APK。原版 App 使用的是共享管理令牌，新版需要重新配对。
2. 电脑网页「设置 → 手机日程同步」生成一次性二维码，用新版 App 扫码。二维码五分钟有效，成功交换后立即失效，不包含电脑管理员令牌。
3. 手动连接时填 `https://sync.example.com`。手机显示六位数字，在电脑同一卡片核对并允许。App 只接受 HTTPS，不再通过局域网明文 HTTP 传递设备凭据。
4. 首次同步完成后，电脑关机或手机断网仍可管理本地日程。保存成功显示“已保存到手机”，待电脑可达后再同步。

旧 App 的连接地址会保留。升级后尚未重新配对时，可以在连接页面查看升级前的只读快照；它不会作为新版数据上传，也不会恢复已经删除的日程。旧后端不支持新协议时明确提示升级。

“仅日期”保留日期本身，不转成午夜时刻。具体时刻通过带时区偏移的接口传输。系统日历暂不直接读写，原有 ICS 订阅继续使用。稍后提醒由电脑服务执行，电脑关机时不会发出新提醒。

## 冲突与离线数据

- 本地保存日程和操作队列是同一次数据库事务。退出、杀进程或重启手机后，待同步操作仍保留。
- 不同字段可自动合并。同一个字段两端改成不同值时，在「同步」页逐项选择手机值或电脑值，再提交。
- 删除与并发编辑需要确认；电脑已经删除的日程不会自动复活。本地修改可以放弃或另存为新日程。
- 放弃某条冲突时，会明确放弃该条日程的全部本地未同步修改，不影响其他日程。
- 同步失败、配对失效、域名指向另一台电脑，都不会自动清空本地编辑。重新配对同一后端可以继续同步。
- 更换电脑前可以导出未同步编辑 JSON；该文件不含令牌。首版导出用于人工恢复和留档，不提供自动导入入口。

App 前台每十秒检查增量，本地操作后立即尝试同步。后台使用 WorkManager 的网络约束与退避重试，另设十五分钟周期检查。安卓的省电策略可能推迟后台任务，周期不代表精确到达时间。

## 固定域名与 Cloudflare Tunnel

在电脑 `.env` 中设置：

```dotenv
NOTICEHUB_MOBILE_BASE_URL=https://sync.example.com
NOTICEHUB_WEB_TOKEN=自行生成的电脑管理令牌
NOTICEHUB_WEB_HOST=127.0.0.1
NOTICEHUB_WEB_PORT=8766
```

改配置后重启服务。`MOBILE_BASE_URL` 仅用于手机配对，不替代整站的 `WEB_BASE_URL`。不要把 Cloudflare 隧道令牌填入上述两项。

本地管理端口默认 8766。隧道仅转发如下手机路径，其他路径返回 404。已有隧道应保留其他主机的规则，将本主机的允许规则放在本主机拒绝规则之前；另一主机的路由不必改动。

```yaml
ingress:
  - hostname: sync.example.com
    path: ^/api/v1/(info|pair/(start|exchange)|sync/(bootstrap|changes)|mutations|tasks/lookup)$
    service: http://127.0.0.1:8766
  - hostname: sync.example.com
    service: http_status:404
  - service: http_status:404
```

Cloudflare 管理的隧道在控制台配置同等的 hostname/path/service 规则。DNS 中为 `notice` 设置启用代理的 CNAME，目标为本隧道 UUID 加 `.cfargotunnel.com`。对 `/api/v1/*` 设置 Cache Rule 为 Bypass；接口本身也返回 `Cache-Control: no-store`。不要给手机路径加需要浏览器验证码或交互登录的规则。

### 本工作区的 Windows 启动方式

下面的三个脚本同时支持 Windows 自带的 PowerShell 5.1 和 PowerShell 7。含中文的 `.ps1` 文件必须保存为带 BOM 的 UTF-8；无 BOM 的 UTF-8 在 5.1 下可能出现 `UnexpectedToken` 等解析错误。启动和停止只影响本工作区记录的进程，打开控制台不会启动 QQ 托管。

为本项目创建独立隧道，并将自己的域名指向该隧道。隧道名称、UUID 和连接令牌只保存在本机配置中。

网页建议仅监听 `127.0.0.1`。示例端口为 8766；如端口被占用，可在 `.env` 中更换，并同步修改隧道目标端口。

```powershell
# 启动电脑服务及隧道连接器
./tools/start_mobile.ps1
# 打开带本机管理员会话的网页，令牌不会打印到终端
./tools/open_console.ps1
# 停止上述脚本启动的进程及其子进程
./tools/stop_mobile.ps1
```

启动脚本默认使用本工作区的 `.venv`、`data/cloudflared.exe` 和 `data/cloudflared.token`；也可传 `-PythonPath`、`-CloudflaredPath`，或者用 `-NoTunnel` 只启动电脑服务。令牌文件和 `.env` 都不提交仓库。脚本记录 PID 与进程启动时间，仅管理本次创建的进程，不接管其他服务。日志在 `logs/mobile-backend.*.log` 与 `logs/mobile-tunnel.*.log`。

脚本运行后进程在后台继续执行。它没有安装开机启动服务；重启电脑后需要再运行一次。数据库迁移前仍应自行备份 `data/`，自动迁移备份不能替代日常备份。

`start_mobile.ps1` 启动的是 `main.py run` 后台服务和隧道，没有运行 `packaging/launcher.py` 托盘宿主，因此不会显示托盘图标。后台在线表示手机可以连接日程服务，不代表 QQ 已开始托管。只有明确开始 NapCat 托管，才会按设置退出普通电脑版 QQ 并启动托管实例；托管未启用时电脑版 QQ 正常登录是预期行为。还需选定接收群并完成登录，才能获取新的 QQ 群消息。

### 真机验收副本

已有正式版与本地调试包签名不同时，不要直接卸载旧版。可运行 `./gradlew.bat :app:assembleDebug -PnoticehubValidation` 构建独立的 `com.noticehub.app.validation`，与旧版并存。它使用独立的本地数据库和凭据；默认构建仍保留原包名。正式覆盖升级必须使用原发行签名。

安卓 beta.17 起两个构建的显示名称都为「群务台」，没有括号；内部包名继续保持各自不变，覆盖安装保留日程与配对。手机只需留新版时，应先确认新版数据与连接正常，再按用户选择卸载旧版及其本地数据。不要删除新版的数据库、WorkManager 数据或 WebView 正常运行文件。

公网入口只提供日程同步。电脑设置、软件安装、NapCat 控制和设备批准继续在电脑网页操作。每台手机有独立设备令牌，电脑可以单独撤销；令牌由 Android Keystore 保护，不交给 WebView。

### 网络安全边界

手机配对、同步和旧连接恢复均要求 HTTPS；已有 HTTP 配对会停止联网，保留本地数据，需改用 HTTPS 重新配对。电脑本机管理网页仍可通过环回 HTTP 打开。

隧道请求通过 `CF-Connecting-IP` 区分访客，并使用独立于本机直连的限流计数。仅当 TCP 对端为环回地址时才信任此字段；局域网直连提供的同名头被忽略。本机进程属于可信边界，因此部署应继续绑定 `127.0.0.1`，避免其他代理通过同一端口转发不可信头。单个来源一分钟内鉴权失败超过 30 次，封锁该来源 60 秒；其他访客和本机管理请求不受该计数影响。

本机隧道传入的 `X-Forwarded-Proto` 必须为 `https`，否则 v1 接口返回 426，并在读取请求体、创建配对或修改日程前停止处理。它不能撤回客户端已经通过 HTTP 发送的凭据，所以必须同时更新手机 App。建议在 Cloudflare 边缘配置 HTTP 跳转 HTTPS；这不能替代客户端发送前校验。

## 协议和数据迁移

`GET /api/v1/info` 返回协议版本、后端身份和启动会话。配对后使用 `Authorization: Bearer <设备令牌>` 访问：

| 接口 | 作用 |
| --- | --- |
| `GET /api/v1/sync/bootstrap` | 固定上界、按 UUID 分页的全量数据 |
| `GET /api/v1/sync/changes` | 按变更序号读取增量及删除记录 |
| `POST /api/v1/mutations` | 新建、修改、状态变更和删除 |
| `POST /api/v1/pair/start`、`POST /api/v1/pair/exchange` | 手动配对与一次性凭据交换 |
| `/api/v1/admin/devices/*` | 电脑管理员的设备列表、批准、票据和撤销 |

同步请求携带后端身份与启动会话。写请求包含操作 ID、日程 UUID、类型、基础版本、修改字段的原值与目标值。原请求重试认同一回执；不同字段按原值和当前值合并，同字段冲突不部分提交。不使用手机时钟决定覆盖顺序。

数据库结构升级到版本 2。升级前为旧库保存 `<原库名>.pre-sync-v1.bak`，补齐历史 UUID、版本和变更记录；能从既有纠错事件确认的人工字段会保留。迁移与日常写入都记录同步账本，已有接口保持返回格式和删除条件。新接口可明确删除任意日程。

同步账本保留独立删除记录及来源键，阻止自动回填重建已删除的同一来源日程。第一版不自动清理变更、删除记录或操作回执。后端重启触发全量校准，但不会清空手机的待同步编辑。

旧版本程序不能直接打开升级后的数据库。回退需要停止服务并恢复升级前备份，同时保留新版数据库及手机未同步编辑。

验收记录见 [手机同步验收](mobile-sync-validation.md)。
