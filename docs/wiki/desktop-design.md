# 电脑端界面设计与维护约束

## Overview

首页首先服务于查看日程、处理待办和新建待办。主导航负责切换待办、最近推送、收件箱、设置；辅助面板承载置顶、快捷操作、概览、接入、订阅群、健康检查与项目信息；设置目录负责查找和修改配置。三个区域不能混用导航职责。

本页记录当前实现，维护依据是 `noticehub/web_static/page.html` 的主题变量与末尾 `#workspace-layout` 样式，以及 `js/desktop-shell.js`、`js/settings.js` 的行为。前置 YAML 提取实际使用的颜色、字号和组件值；深色值以 `dark-` 区分，对应同名 CSS 变量在深色主题下的取值。修改时应核对完整 CSS 层叠，不能只看最后一个样式块。架构和业务数据流见 [架构](architecture.md)。

## Colors

浅色工作区使用浅灰背景、白色内容面和深绿文字。青绿色用于当前导航、链接、选择状态及焦点；红色表示逾期或错误，琥珀色表示待处理、候选和提醒。语义状态还需保留文字或图标，不能只依靠底色区分。

深色工作区使用略带绿相的炭灰背景与墨绿灰内容面，文字为柔和的灰白和灰绿，青绿强调色降低饱和度。卡片边界使用 `dark-line-soft`，控件边界沿用对比更高的 `dark-line`；不把输入框和按钮边界一起压暗。主题预览和系统主题色与实际配色同步。

页面可见背景使用 `paper-alt`，摘要、设置容器和辅助面板使用 `paper`；`line` 分隔面板和表单行，`muted` 承载说明文字。新增区域应沿用这些 CSS 变量，避免把浅色值直接写进深色页面。主题切换同时替换正文、背景、边界和状态色，不能仅反转页面底色。

浅色主按钮使用独立的 `primary-button` 色；深色主按钮使用 `dark-primary-fill` 底、`dark-teal` 边框和 `dark-ink` 文字，悬停时改为强调色底。选中导航使用强调色的柔和底片，与提交按钮保持层级差异。

## Typography

字体使用系统字体栈，中文回退到苹方、微软雅黑，不依赖外部字体下载。前置 `body` 是宽度至少 900px 时的正文字号；更窄窗口的基础正文为 15px，行高保持 1.5。设置说明和表单多使用 `form`，辅助说明使用 `note`，不要把所有内容统一缩成小字。

首页摘要、工作区标题、设置页标题各有独立层级。设置页说明文字行高 1.75、最大宽度 75ch；具体偏好项的补充说明行高 1.65。标题、群名、任务内容和长地址应允许换行，表单列使用 `min-width:0` 避免长内容撑破网格。

## Layout

宽屏把主导航固定在左侧，首页正文再分为待办主列与辅助面板列。清单与月历互斥显示，共用日期、状态和关键词筛选；清单默认按最近到期排序，完整概览已移除。辅助栏吸附在距顶部 90px 处，最大高度为 `calc(100dvh - 112px)`，独立滚动，展开不改变主列内容的位置。接入进度折入可展开的指引。离开待办视图后隐藏待办工具栏、筛选、指引和辅助面板，给当前页面完整的内容宽度。

| 视口宽度 | 主布局与设置布局 |
| --- | --- |
| 至少 1600px | 延续固定左导航；辅助面板宽 340px，设置目录宽 232px，设置正文内边距为上下 36px、左右 48px。 |
| 1024–1599px | 主导航宽 168px，距左 16px、距顶 92px；正文左边距 208px、右边距 24px、宽度 `calc(100% - 232px)`。待办主列自适应，辅助面板宽 300px，列间距 24px。设置目录宽 208px，正文内边距 `28px 32px 40px`。 |
| 701–1023px | 主导航横向排列并吸附于顶部 70px；工作区变为单列。设置目录宽 180px，正文内边距 `24px 20px`；目录吸附于顶部 136px。 |
| 不超过 700px | 设置目录移至正文上方，取消吸附和内部高度限制，子页面入口可换行；正文内边距 `20px 16px`，文本输入和选择框独占一行。设置标题降至 21px，首页摘要标题降至 23px。 |

宽屏设置目录吸附于顶部 90px，最大高度 `calc(100vh - 110px)`，超出部分独立滚动；设置正文最大内容宽度为 880px。首页筛选条在宽屏横向排列，窄屏分行，不通过扩大概览卡片来占据主区。

`body` 至少覆盖整个动态视口高度，短内容也保持完整的页面背景。桌面端 `body` 不额外预留底部空间，工作区末尾由 `main` 统一保留 24px 间距。辅助面板收起后按可见内容计算高度，不保留展开占位；内容不足一屏时，下方为页面背景，不强行拉长待办卡片。

## Elevation & Depth

工作区主要依靠背景、边框和留白分层。摘要、任务、通知、设置面板和内容面取消常驻阴影与三维位移；背景流动装饰不再显示，任务悬停和聚焦不再抬升。按钮仍保留既有悬停反馈：上移 1px，阴影为 `0 4px 10px rgba(20,49,39,.12)`；按压缩放为 0.98。不要把“内容面无阴影”扩展成“所有交互无反馈”。

保留系统减少动效和应用动效偏好。减少动效时取消动画和过渡，不得影响切页、展开、定位或保存反馈；功能完成不能依赖动画结束事件。

## Shapes

主要内容面、摘要和设置外框使用 `surface` 圆角；任务使用 `task` 圆角，按钮、搜索框和输入框使用 `control` 圆角。设置表单行不再逐项嵌套卡片，而是用底部分隔线形成连续阅读顺序。主题选择保留独立预览卡，选中时使用 2px 强调色边框。

边界通常为 1px 实线。拖动落点使用 2px 强调色虚线，拖动中的面板透明度为 0.5；这类反馈仅用于当前操作，不作为常驻装饰。

## Components

侧栏保留 `overscroll-behavior-y:auto` 作为原生回退。宽屏的 `js/rail-scroll.js` 将同一笔纵向滚动量沿栏内可滚动列表、侧栏、页面依次分配，跨边界时不重新启动动画。鼠标滚轮使用短缓动，小幅像素输入直接传递；关闭动效时不缓动。反向输入、指针按下、键盘操作、切换区域及窗口状态变化会取消未完成的缓动，缩放与横向操作交回浏览器。

### 主导航与键盘焦点

宽屏导航按钮最小高度 48px，图标为 19px，图标与文字间距 12px；设置入口与前三项另留 24px 间距。竖向导航支持上下方向键，横向导航支持左右方向键，两者均支持 Home、End，`aria-orientation` 随 1024px 断点同步。选中状态同步可访问性属性，不能只有视觉高亮。设置分类使用 `aria-expanded`，子页面使用 `aria-current` 和 `aria-controls`；切换设置页时将焦点送至页标题，并定位设置容器。

焦点轮廓为 2px 实线。当前基础样式带有 `!important`，实际 `outline-offset` 为 2px；深色主题另以 `!important` 将轮廓色改为主题强调色。维护时需注意新工作区中单独声明的 3px 偏移不会覆盖该规则，不能据此推断实际渲染值。

### 辅助面板

面板标题按钮控制折叠，正文与标题保持同一节点；折叠同步 `hidden`、`aria-expanded` 和视觉类。整理模式显示上移、下移、拖动与恢复默认操作，拖动之外必须保留按钮排序路径。到达排序边界后，焦点交回另一个可用排序按钮，并通过状态区域报告结果。

本机偏好键为 `nh_workspace_v1`，仅保存已知面板 ID 的去重顺序和布尔折叠状态。未知面板被忽略，遗漏面板补入默认顺序；JSON 损坏或存储不可用时仍能操作。恢复默认保留置顶展开，QQ 接入按是否需要登录展开，其余面板收起。初次载入时 QQ 接入面板也随二维码可见状态调整；用户手动折叠选择优先于状态轮询。

### 待办编辑与收件箱操作

新建与编辑共用 `task-editor.js` 管理的原生 `dialog`，挂在工作区外，列表重绘不影响表单。内容、截止时间、日期模式和备注同屏填写；原生弹窗约束键盘焦点，关闭后返回入口。未保存内容离开前先确认；保存失败保留输入并在弹窗中显示原因；请求进行中禁止重复提交。编辑打开时读取并锁定版本，列表轮询不能偷偷替换基线。新建成功后刷新并定位新任务，已写入但刷新失败应明确说明，不再提交创建请求。

清单与收件箱均提供清除筛选，月历提供返回当月的「今天」。收件箱正文直接预览，长文按需展开；回溯工具默认收起，运行中的任务恢复显示进度。已转待办的入口用于定位原事项，不作为禁用状态展示。收件箱切换查询时取消旧请求并校验请求序号，加载更多期间不能再次提交相同分页。

全站操作结果显示在视口底部，成功提示定时收起，失败信息保留并可关闭；输入表单的错误留在表单附近。所有新增表面沿用现有主题变量，窄屏弹窗限制在动态视口内，正文区域可滚动。

### 设置目录与表单

设置分为五类、十八页，搜索匹配分类名、页名、说明和页面文本，结果返回到对应页面，不负责提交配置。点击一级分类时，返回当前设置会话内该分类上次访问的子页，首次访问才进入第一项。

| 分类 | 子页面 |
| --- | --- |
| 常用设置 | 外观与布局、托管与启动 |
| 消息来源 | QQ 与订阅群、微信、钉钉、学习通、历史回溯 |
| 通知与提取 | 消息推送、AI 摘要、识别规则 |
| 日程与数据 | 手机日程同步、日历订阅、数据备份 |
| 系统与帮助 | 首次配置、运行信息、版本更新、服务公告、关于与支持 |

目录由 `desktop-shell.js` 组织，表单仍由 `settings.js` 和各功能模块创建、读取与保存。分类操作移动已有 DOM，不复制表单，不重新绑定业务事件；子页面切换仅切换显示状态，保留尚未提交的输入，不触发保存。部分设置原本在控件变化时自动保存，其他设置有明确保存按钮，这些业务行为不由切页逻辑改写。运行信息的异步结果写入独立容器，不能向设置根节点追加游离内容。

设置搜索框最小高度 40px；常规表单行最小高度 64px，左右两侧分置说明与控件。宽屏文本框和选择框宽度为 45%、最大 360px、最小高度 42px；复选框为 18px。折叠标题、搜索结果及一般按钮保留清晰的点击区域，不把文字本身当作唯一可点击范围。

### QQ 接入与旧入口兼容

QQ 接入和订阅群在首页侧栏与设置中复用同一份 DOM。进入设置时，两个节点移入“QQ 与订阅群”并展开；离开设置时归还侧栏、恢复进入前的折叠状态和顺序。设置整体重建前必须先归还节点，避免清空仍在登录、扫码或轮询的控件。

平台接入检查只在「系统与帮助 → 首次配置」展示，不在首页生成未完成数量提示。检查面板复用同一节点，设置重建时重新挂载，保留展开状态和操作监听；各平台仍提供原有的设置跳转、连接动作和手动操作说明。跳转只展开目标页一次，用户切走后停止定位，避免后续帧把页面切回。

向导、快捷操作与锚点定位应走统一展开逻辑。`scrollTargetIntoView` 先调用 `NhDesktop.reveal` 展开目标设置页、侧栏和祖先 `details`，再测量目标尺寸；目标高于等于视口时顶边对齐，并预留页头底边加 8px 的空间，其余目标居中。顺序不能颠倒，否则隐藏内容的尺寸和定位会失真。

## Do's and Don'ts

- 保持日程与待办的优先级，新增配置项进入现有分类；辅助信息默认收敛到可展开的面板或指引。
- 复用原有控件、请求和保存函数；新增异步内容要有稳定的所属页面与容器。
- 布局偏好只保存展示状态，不写入访问令牌、密钥、Cookie、登录凭证或表单草稿。
- 服务端 API 负责业务状态。不能依据侧栏是否展开推断 QQ 在线、托管成功或配置已保存；写动作之后仍需沿用相应功能的状态刷新和缓存失效。
- 不在设置切页或搜索时隐式保存，不通过复制 DOM 制造第二套登录或订阅控件。
- 不以截图中的位置代替交互验证。维护时需核对折叠排序、键盘路径、未保存输入、QQ 节点归还和旧入口定位；本页记录实现约束，不代替测试与真实接口验收。
