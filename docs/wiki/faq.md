# 常见问题

## 打开电脑页面时 PowerShell 报 UnexpectedToken

若 `tools/open_console.ps1` 报第 7 行包含意外标记，或启动、停止脚本在中文附近报解析错误，先更新脚本文件。Windows PowerShell 5.1 会将无 BOM 的 UTF-8 按系统代码页读取；这三个脚本现已统一为带 BOM 的 UTF-8，可直接在系统 PowerShell 中执行。该错误发生在脚本解析阶段，与 QQ 登录及日历后端是否在线无关。

电脑页面需要本机管理会话，首次请使用 `tools/open_console.ps1` 打开；裸地址返回 401 表示缺少会话，不表示 QQ 未登录。页面首次出现平台接入向导时，可以选「稍后配置」继续使用日历和手动日程。

## 手机固定域名打开是 404？

`sync.example.com` 只提供新版手机接口，浏览器打开首页返回 404 是预期行为。检查连通性用 `/api/v1/info`，配对和设备批准在本机管理网页完成。可执行 `tools/open_console.ps1` 打开管理页；启动、停止及升级说明见 [手机日程同步](mobile-sync.md)。

## 手机保存后电脑为什么没变？

“已保存到手机”说明本地数据和操作队列已写入；电脑可达后才会变成“已同步”。电脑关机、网络不通、域名未配置或配对失效时，编辑仍保留。查看 App「同步」页的待同步数量和失败原因；同字段并发修改需要选择保留值。不要通过卸载 App 排查，这会删除未同步数据。

新旧二维码不通用。新版请使用电脑「手机日程同步」卡片的五分钟一次性二维码，而不是旧版「手机 App」卡片。后端重启会重新校准，详见 [手机日程同步](mobile-sync.md)。

## 结束托管后普通 QQ 提示账号已登录

先检查是否有使用Agendum专用资料目录的 QQ 残留。在 PowerShell 中运行：

```powershell
Get-CimInstance Win32_Process | Where-Object { $_.Name -eq 'QQ.exe' } |
  Select-Object ProcessId, ParentProcessId, CommandLine | Format-List
```

核对 `--user-data-dir` 是否**完整等于**本安装的数据目录下的 `napcat-profile`，不要只按 `QQ.exe` 进程名结束进程，以免关闭普通 QQ 或其他实例。确认是残留的托管 QQ 后，可在任务管理器按 PID 结束该进程树，或运行 `taskkill.exe /PID <确认过的主进程PID> /T /F`。PID 每次启动可能改变，不能照搬其他机器的进程号。清理后重新查看进程列表和 `Get-NetTCPConnection -State Listen -LocalPort 3001`；端口仍被占用时还要核对占用者。

典型故障是启动器已经退出，但带本安装专用资料目录参数的 QQ 子进程仍在运行。清理后应同时复查进程树和监听端口，不能仅凭启动器消失判断停止成功。

代码原因已确认：旧版 `noticehub/napcat_admin.py` 的 `stop()` 和 `_matching_pids()` 只匹配 NapCat 启动器，快速退出路径在找不到启动器时直接报告已停止；启动器先退出后，独立存活的 QQ 无法被清理。相同的判断也用于启动去重，可能在等待登录时重复启动。这一缺口能解释上述残留，但当时没有日志记录启动器退出的完整时序。

未发布版本已修复：启动、状态查询和停止按本安装完整的 `--user-data-dir` 参数识别启动器与 QQ，支持目录中的空格、大小写和路径分隔符差异。停止不再依赖引擎文件仍然存在，也不会只凭共用的引擎安装路径结束其他实例。清理后用新进程快照复查；仍有残留、查询失败或超时就返回失败并保留托管状态，避免一边占着账号一边恢复普通 QQ。程序退出时也会记录失败，五秒预算到期后继续退出，之后可重新打开程序重试结束托管。源码修复需要重新打包安装后才会用于现有安装版。

验证范围：回归覆盖启动器缺失、引擎文件缺失、重复启动、资料目录前缀相同、普通 QQ 与其他实例共存、进程树清理、失败状态保留及总预算。Windows 实际进程验证使用临时编译的同名测试程序，通过真实 tasklist、CIM 和 taskkill 检查归属及清理，未连接真实 QQ 账号；普通 QQ 的实际登录结果仍需安装修复版后验证。

## QQ 被风控踢下线

先分清是哪一种掉线。

**普通掉线**：电脑休眠、网络断了、QQ 被关掉。重新启动 NapCat，回向导扫码，正常处理。

**疑似被腾讯风控**：刚扫码几分钟就掉、反复扫反复掉、手机 QQ 上收到安全提醒。**这时不要反复重扫。** NapCat 是第三方 QQ 协议客户端，腾讯会主动识别这类登录，每次重连都是一次新的识别样本，连续重试只会让判定更重。

正确做法：停几个小时甚至一两天，期间用手机上的官方 QQ 正常使用这个账号，确认账号本身没受限，再回来试一次。账号已经被限制登录就按腾讯的提示申诉，这个项目帮不上忙。

长期看，给机器人单独申请一个 QQ 小号最省事。

## 二维码扫了没反应 / 一直是旧码

二维码由 NapCat 自己隔一段时间换新。页面会显示已等多少秒，别靠掐表。

等了 90 秒还没动静就点「重启引擎」再扫。订阅二维码的内容是订阅地址本身，地址不变码就不变，所以设置里的「刷新二维码」在没变时会直接告诉你「订阅地址没变」。

## 端口被占

服务默认用 8766（网页）、8765（NapCat 上报）、3001（反查 NapCat）。启动报端口占用时：

1. 先确认不是自己开着的另一个Agendum：任务管理器里看有没有多出来的 `QQ-Notice-Hub.exe` / `qq-live-digest.exe`。
2. 改了端口就得跟着改 `.env` 里的 `NOTICEHUB_WEB_PORT` / `NOTICEHUB_ONEBOT_PORT`，并重启服务。
3. 改完端口，手机端和日历订阅的地址也要跟着换。

## 手机连不上

先按顺序排：

1. **防火墙**（最常见）。在跑Agendum的那台电脑上用管理员 PowerShell 执行：
   ```powershell
   netsh advfirewall firewall add rule name="notice-hub 8766" dir=in action=allow protocol=TCP localport=8766
   ```
   新版也可以直接点页面上的「一键修复」，它会弹一次管理员权限自动加规则。
2. **同一个 Wi-Fi、地址没选错**。`ipconfig` 看「无线局域网适配器 WLAN」的 IPv4 地址；如果页面给的是 10.x / 172.x 这类 Tailscale、VMware、WSL 的虚拟网卡地址，手机永远连不上。升级到 1.1.0-beta.8 或更新版本会自动避开。
3. **用流量**要开公网。点「开通公网入口」，会装好并拉起 Tailscale；登录这一步得你自己用账号登一次，登完程序自动开 Funnel 并给出地址。不登录就只有局域网地址。
4. 还不行就生成诊断包：`python main.py doctor --bundle`，把那个 zip 发过来。

## 登录过期

**学习通**：Cookie 过期后待办页顶部会出红色提示。重新登录学习通，回设置页点「自动获取学习通 Cookie」；不行就展开手工方式，从浏览器开发者工具里复制 Cookie 完整值粘进去。

**微信**：状态行显示「未找到微信」或读取失败时，按提示的原因处理——最常见是微信版本不对（这个功能要 4.0 的 Weixin.exe），或者先完全退出微信再重试。扫描失败时页面直接给「重试扫描」按钮。

**QQ**：见上面「QQ 被风控踢下线」。

## 更新失败

| 现象 | 怎么办 |
| --- | --- |
| 检查更新转圈没结果 | 网络不通。隔一会儿再点；一直不行就手动下 zip 覆盖 |
| 下载很慢或提示手动下载 | 从本仓库的发布页下载 ZIP，核对 SHA-256 后按[安装与升级](install.md)的步骤覆盖 |
| 覆盖时报「拒绝访问」 | 旧目录里有文件被设成只读：右键 → 属性 → 取消「只读」。也可能是程序还在跑，先托盘「退出」 |
| 装完服务没起来 | 程序会自动重试 3 次，仍失败会提示手动启动；看 `logs\launcher.log` |
| 更新后手机或日历连不上 | 只要令牌没变地址就没变。改过令牌就得重新订阅日历 |

`data\` 和 `.env` 不会被动，安装包只覆盖程序文件。

## 网页打不开 / 托盘不见了

- 网页打不开：程序没在跑，重新双击 `QQ-Notice-Hub.exe`。
- 托盘图标不见了：软件被退出或没启动。重新双击，或从桌面快捷方式进。
- 关掉网页但软件还在跑是正常的，它常驻在托盘里。

## 收件箱一直是空的

顺序问题：先点「① 回溯聊天记录」把消息抓下来，再点「② 提取通知」判定。只点一个不会有结果。

回溯只能拿到 NapCat 本地缓存里还剩的消息，越早越可能被 QQ 清掉。点「探测最早时间」看实际边界。

## 一直没有新待办

按顺序看：群有没有勾上并保存 → 群里这段时间是不是真的没通知 → 电脑是不是在休眠。

另外确认推送通道配了没有。没配推送也能用，只是手机上收不到提醒，得自己打开网页看。

更多配置项见 [配置](config.md)，安装与升级见 [安装与升级](install.md)。
